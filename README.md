# Adrobot Campaign Console

Создание кампаний и управление офферами через Keitaro Admin API. Сервер на FastAPI и SQLAlchemy, миграции на Alembic. Интерфейс работает в браузере без отдельной сборки фронтенда.

## Запуск

Из корня проекта, с Python 3.11 или новее:

```sh
python -m venv .venv
```

Активируйте окружение командой `.\.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в Bash. Затем выполните:

```sh
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app
```

Интерфейс доступен по адресу <http://127.0.0.1:8000>, Swagger приложения — по адресу <http://127.0.0.1:8000/docs>. Для тестов установите `pytest` и запустите `python -m pytest -q`.

## Деморежим

Режим по умолчанию. Для создания введите название, код `AU` и оффер `3749`. Домен, группа и источник уже доступны в списках. Затем откройте редактор и добавьте офферы `3717` и `4021`. Три активных оффера получают доли 34%, 33% и 33%. При удалении одного из них доли становятся 50% и 50%. Демокампании и журнал изменений хранятся в SQLite. Демодомен иллюстрирует формат ссылки.

## Подключение к Keitaro

Новые кампании получают префикс `test_galkin_`, как требует ТЗ. Можно ввести `campaign1` или `test_galkin_campaign1`. В обоих случаях итоговое имя одинаковое. Для другого участника задайте его префикс в `CAMPAIGN_PREFIX`.

Скопируйте `.env.example` в `.env`, установите `KEITARO_MODE=live`, заполните `KEITARO_URL` адресом своего трекера и `KEITARO_API_KEY` ключом из админки. Ключ передаётся только сервером в заголовке `Api-Key`. Выберите существующий домен, группу кампаний и источник из загруженных справочников. Ключу нужен доступ к справочникам, офферам, кампаниям и потокам.

Кампания сначала создаётся выключенной, затем добавляются приоритетный поток с фильтром страны и переходом на Google и поток по умолчанию с оффером. После настройки кампания включается. Если Keitaro отклонит один из шагов, интерфейс покажет ID кампании для проверки в трекере. Создание и изменения офферов записываются в SQL-журнал после подтверждения операции.

В редакторе можно выбрать существующую кампанию и изменить офферы в потоках со схемой `landings`. При изменении состава активные офферы получают равные целые доли с распределением остатка по порядку, выключенные сохраняют статус. Последний активный оффер защищён от удаления. При сохранении сервер заново читает поток и проверяет версию списка, чтобы обнаружить устаревшую форму. Тестовый сервер рассчитан на один локальный процесс и одного доверенного оператора.

Схемы запросов сверены с [Keitaro Admin API](https://admin-api.docs.keitaro.io/). Проверка на рабочем трекере требует URL и ключа Keitaro.
